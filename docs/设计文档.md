> 项目代号：**dsh-vault**（密码小程序）
> 版本：v0.1 设计稿 · 2026-11
> 状态：待评审 → 评审通过后进入 MVP 实现
> 姊妹篇：[用户流程与部署清单](用户流程与部署清单.md) —— 完整用户旅程、要搭建的应用与要使用的服务

## 1. 目标与非目标

### 1.1 目标

1. **登记**：用户通过 IM 通道、DSH 对话框、GUI 表单或本地生成四种路径，把密码 / API key / SSH 私钥 / 2FA 种子等秘密交给插件；插件记录用途系统、账号、有效期、录入时间等元数据，秘密本体**立即加密**。
2. **云端同步**：密文可安全上传到云（对象存储 / WebDAV / 私有 git 仓库），实现多设备可用；**云端在任何时刻都接触不到明文**。
3. **调取**：用户需要时，通过密保问题挑战 + 解锁验证，以三种受控出口获得秘密：脱敏回显、剪贴板（自动清除）、代用执行（明文直接用于目标系统，不回显）。
4. **保密铁律**：明文不进入模型上下文、不进入会话日志（尽力而为，见 §11）、不进入命令行参数、不进入任何报告与产物。
5. **生命周期**：到期提醒、轮换引导、版本历史、审计日志。

### 1.2 非目标

- 不做浏览器自动填表（可后续对接 Bitwarden CLI 等）。
- 不做多用户 / 团队权限体系（团队场景建议直接换 Infisical/OpenBao 后端，见 §4）。
- 不自研密码学原语：全部使用成熟库（age、libsodium/Argon2、AES-GCM）。
- 不承诺对抗"用户设备已被完全控制且解锁态"的攻击者（见 §11 威胁模型边界）。

## 2. 威胁模型

| # | 对手 / 风险 | 能力 | 对策 |
|---|---|---|---|
| T1 | 网络窃听者 | 截获传输流量 | TLS 1.3 + 应用层 E2EE（密文上传，双保险） |
| T2 | 云存储运营商 / 被拖库的云服务 | 读到云端全部数据 | **零知识**：云端只有密文与无意义元数据（§6.2） |
| T3 | LLM / 模型服务商 | 看到进入上下文的任何内容 | 明文不进上下文：录入即加密、调取走脱敏/剪贴板/代用三出口（§3） |
| T4 | 会话日志与投影缓存 | 持久化对话内容 | 回执只含脱敏摘要；`vault scrub` 事后打码；高价值密钥不走聊天录入（§6.1 路径 C/D） |
| T5 | IM 平台 | 留存用户发出的消息 | 无法技术上消除；产品层警示 + 引导改用 GUI 表单/本地生成路径（§11.3） |
| T6 | 同机其他会话 / 子代理 / 沙箱内进程 | 读工作区文件 | vault 存放在工作区之外（`~/.config/dsh-vault`），DSH workspace-write 沙箱天然拦截；仅插件 host 进程可触达 |
| T7 | 暴力破解密保 / 主密码 | 无限次尝试 | Argon2id 哈希 + 限速 + 连续失败锁定 + 告警 + 审计（§6.4） |
| T8 | 设备失窃（锁屏态） | 读磁盘文件 | 静态加密；私钥文件 0600；可选 OS keychain / 硬件密钥；空闲自动锁定（内存密钥超时清零） |
| T9 | 私钥丢失 | 全库不可解 | Shamir 2-of-3 分片备份 + 加密导出（§9.4） |
| T10 | 胁迫场景 | 强迫用户解锁 | 紧急销毁口令（duress answer）：特定密保答案触发本地密钥销毁（§6.7，可选启用） |

## 3. 关键架构决策：明文永不经过模型

DSH 的事实约束（已在本机检出核实）：

- 对话框 / IM 通道收到的消息**必然进入模型上下文**并写入会话日志；
- `ask_user_question` 的用户答案**同样回传给模型**；
- 审批策略（ask）下，bash 命令文本对审批人可见 → **命令行参数里不能放明文**；
- 受管 bash 环境已有 `DSH_*` 变量注入机制 → 可作为"代用"场景的密钥注入通道参考。

由此推出三条设计铁律：

1. **录入方向**：模型可能短暂看到明文（聊天路径），但插件工具收到后**在 host 进程内立即加密**，工具返回值只含脱敏摘要（如 `ghp_****Xy2`、指纹哈希前 8 位），任何后续轮次不再有明文。
2. **解锁方向**：主密码**永不经过模型**——通过 GUI 解锁对话框（client 插件直连 host 服务，走独立 RPC 通道）或用户在真实终端执行 `vault unlock` 输入。密保问答经模型，但答案存 Argon2id 哈希，问答只是"在场证明 + 审批门槛"，**不是加密密钥**；真正的保密性由"解密私钥从未离开 host 进程"保证。
3. **调取方向**：解密发生在 helper 子进程内，明文只有三个出口（脱敏回显 / 剪贴板 / 代用），模型收到的工具结果永远是状态 + 脱敏信息。

## 4. 方案对比与选型

### 4.1 候选方案

| 方案 | 架构 | 云端可见明文 | 多设备 | 团队 | 工程量 | 主要风险 |
|---|---|---|---|---|---|---|
| A. 纯本地自制加密库 | 插件自管加密文件，不上云 | — | ❌ | ❌ | 小 | 私钥/文件管理全靠自己；无同步 |
| B. **零知识 E2EE + 哑云存储（推荐主干）** | 本地 age 信封加密 → 密文上传任意云存储 | ❌ | ✅ | 弱 | 中 | 私钥丢失=全库丢失（用 §9.4 备份对冲） |
| C. 自托管 Infisical / OpenBao + 瘦客户端插件 | 服务端持有秘密（服务端加密），插件调 API | ⚠️ 服务端进程可见 | ✅ | ✅ | 中 | 需要运维一个服务；信任服务端实现 |
| D. 云厂商 KMS 凭据管家（阿里云/腾讯云/AWS） | 信封加密由云 KMS/HSM 托管，IAM 控权 | ⚠️ 解密时云侧可见 | ✅ | ✅ | 小-中 | 绑定单一云厂商；IAM 配置错误即泄露 |
| E. SaaS 密码管理器（Bitwarden/1Password）+ CLI 桥接 | 插件包一层 CLI | ❌（E2EE SaaS） | ✅ | ✅ | 最小 | 功能受限于其 CLI；agent 集成粒度粗 |

### 4.2 选型结论

**主干 = B（零知识 E2EE），存储后端做成可插拔**：

- 云同步的"安全"上限由 E2EE 决定：TLS 只防窃听（T1），**防不了 T2**。B 方案下云端只是加密 blob 的搬运工，对象存储 / WebDAV / 私有 git 仓皆可，无厂商绑定、无服务运维。
- **可选后端 = C**：若未来需要团队共享、动态凭据、租约式短期令牌，把 storage backend 从"哑云 blob"切换为 Infisical/OpenBao API，插件的工具面与加密边界不变（backend 接口化，见 §7.3）。
- E 作为逃生舱：`vault import` 支持 Bitwarden/1Password CSV 导入，用户可随时整体迁出。

```
│      │              │               │(不经模型)          │          │
│      ▼              ▼               ▼                    ▼          │
│ ┌─────────────────────────────────────────────────────────────┐    │
│ │              dsh-vault host 插件 (cordis)                    │    │
│ │  vault 服务 ── 工具注册 ── 审计 ── 到期巡检(goal/job)         │    │
│ │      │                                                       │    │
│ │      ▼                                                       │    │
│ │  helper 子进程（唯一接触明文的地方）                          │    │
│ │   · age 加/解密 · Argon2id · 剪贴板 · 代用 HTTP/env 注入      │    │
│ └──────┬──────────────────────────────┬───────────────────────┘    │
│        ▼                              ▼                            │
│  本地 vault 存储                 OS keychain(可选)                  │
│  ~/.config/dsh-vault/0700                                          │
│  （工作区之外 → DSH 沙箱拦截其他会话读取）                          │
└────────┼───────────────────────────────────────────────────────────┘
         │ 仅密文 + 脱敏元数据（TLS）
         ▼
┌─────────────────────────── 云（不可信） ───────────────────────────┐
│  对象存储 / WebDAV / 私有 git 仓        （可选）Infisical/OpenBao   │
│  · *.age 密文 blob                     · 团队/动态凭据后端          │

└─────────────────────────────────────────────────────────────────────┘
```

### 5.1 DSH 四件套

| 组件 | 职责 |
|---|---|
| **host 插件**（cordis） | 提供 `vaultService`；注册模型可见工具（§8.1）；审计日志；到期巡检后台 job；与 client 插件的解锁 RPC 通道 |
| **client UI 插件** | GUI"解锁对话框"（主密码直连 host，不经模型）；"保险库浏览页"（仅元数据：系统/账号/有效期/录入时间，无明文，无密文）；到期提醒卡片 |
| **skill（SKILL.md）** | 教 agent：何时用哪个工具；铁律（不复述明文、不把密钥写进命令行/报告/代码、发现明文立即建议登记+打码） |
| **helper CLI**（`dsh-vault-cli`） | 独立可执行：`unlock/add/list/get/use/sync/backup/...`；host 插件内部调用它，用户也可在真实终端直接使用（此时主密码走 tty，天然不经模型） |

## 6. 核心流程

### 6.1 登记（四条路径，安全性递减排序）

| 路径 | 流程 | 明文经过模型？ | 适用 |
|---|---|---|---|
| **D. 本地生成** | `vault_generate`：helper 用 CSPRNG 生成强密码/密钥 → 直接加密入库 → 返回脱敏摘要；用户需要时走调取 | ❌ 全程不经过 | 新注册账号、新申请 API key（**最安全，默认推荐**） |
| **C. GUI 表单** | client 插件表单 → 直连 host RPC → 加密入库 | ❌ | 存量密钥录入 |
| **B. 聊天/IM 录入** | 用户发消息 → agent 识别意图调 `vault_register(secret=...)` → host 立即加密 → 回执脱敏摘要 | ⚠️ 一次（本轮上下文+会话日志） | 便捷场景；skill 要求 agent 回执绝不复述，并提示可用 `vault scrub` |
| **A. 文件移交** | 用户把密钥放进工作区临时文件 → agent 调 `vault_register --from-file`（helper 读文件，不打印内容）→ 入库后安全删除（覆写+unlink） | ❌（agent 不读文件内容） | 长密钥/私钥文件 |

登记元数据（明文可查，供检索）：

```jsonc
{
  "id": "vlt_01J8ZK...",            // ULID
  "kind": "password|api_key|ssh_key|totp_seed|mnemonic|other",
  "system": "GitHub",                // 用在哪个系统
  "url": "https://github.com",
  "account": "user@example.com",
  "aliases": ["gh 令牌", "代码仓库"], // 自然语言检索用
  "tags": ["work", "ci"],
  "expires_at": "2026-12-31",        // 有效期（可空=长期）
  "created_at": "2026-11-01T12:00:00Z", // 录入时间
  "updated_at": "...",
  "source": "chat|gui|cli|generated",   // 录入通道
  "note": "……",                      // 备注（不含明文）
  "fingerprint": "sha256:ab12…(前8位)", // 去重/重复使用检测
  "strength": "strong|medium|weak",     // host 侧计算，明文不出 helper
  "versions": [ { "ver": 3, "created_at": "…" } ] // 历史（密文各自独立）
}
```

### 6.2 安全上传（发给云）

信封加密（age，X25519）：

```
secret ──AES-256-GCM(数据密钥)──▶ ciphertext
数据密钥 ──age encrypt(vault 公钥)──▶ wrapped_key      （合成一个 .age 文件）
上传 { id }.age + sync-manifest.json  ──TLS──▶ 云存储
```

- **vault 私钥永不上云**，只存本地（0600 文件，可选迁入 OS keychain）。
- 云端可见的全部信息：密文 blob、ULID、同步版本向量。元数据（系统名/账号）**默认不上云**；开启"便利同步"选项时才上传元数据的加密副本（同一公钥加密）。
- 同步协议：`sync-manifest.json` 记录每条目的 `updated_at` + 内容哈希；`vault sync` 做 last-write-wins 合并，冲突条目保留双版本待用户裁决。
- 换云 = 换个 blob 目录，零迁移成本。

### 6.3 调取（从云/本地安全取回）

```
用户: "把 GitHub 的 token 给我" / "用测试环境 key 调一下 X 接口"
  │
  ▼
① 定位条目       vault_list / 模糊匹配（系统、别名、标签）——仅元数据
  ▼
② 密保挑战       vault_challenge：host 随机抽 2 问 → ask_user_question 呈现
                 → 答案回传 → host 侧 Argon2id 哈希比对（限速+锁定见 §6.4）
  ▼
③ 解锁态检查     vault 私钥是否在内存（解锁态）？
                 否 → GUI 解锁对话框 / 终端 `vault unlock`（主密码不经模型）
  ▼
④ 审批           走 DSH ask 审批：审批卡显示"调取 GitHub token → 出口:剪贴板"（无明文）
  ▼
⑤ 出口（三选一，用户在请求中指定或默认脱敏）
   a. 脱敏回显   `ghp_****Xy2`（前3后3），模型可见，用于人工核对
   b. 剪贴板     helper 写入系统剪贴板，60s 后自动覆写清除；模型只收到"已复制"
   c. 代用       vault_use：helper 子进程解密 → 注入环境变量/HTTP 头执行目标操作
                 → stdout 只回状态码与脱敏日志；或注入受管后台 job 的 env（DSH_* 风格）
  ▼
⑥ 审计           追加审计日志：时间/条目/出口/挑战结果/审批人
```

TOTP 特例：`vault_totp` 现算 6 位码可直接回显——码 30 秒失效，风险可接受。

### 6.4 防爆破

- 密保答案：Argon2id（m=64MB, t=3, p=1）逐条加盐哈希存储。
- 挑战失败：指数退避（1s/5s/30s/5m），连续 5 次失败 → vault 锁定 30 分钟 + GUI/IM 告警 + 审计红条。
- 主密码错误同样计数；连续 10 次 → 要求紧急恢复流程（§9.4 分片备份）。

### 6.5 到期提醒与轮换

- host 插件注册每日巡检 job：`expires_at` 距今 ≤ 14/7/1 天 → GUI 提醒卡片 +（若绑定 IM 通道）IM 推送，内容仅元数据。
- 轮换引导：`vault_rotate(id)` → 生成新密钥（路径 D）→ 旧版本进历史（保留 90 天）→ 提示用户去目标系统替换 → 确认后作废旧版本。
- 弱密码/重复密码审计：入库时 helper 计算强度分与指纹；`vault_audit_report` 输出脱敏清单（"3 条弱密码、2 组重复使用"）。

### 6.6 泄密扫描（增值）

- `vault_scan_workspace`：对当前项目文件与 git 历史跑内置规则（`sk-[A-Za-z0-9]{20,}`、`AKIA[0-9A-Z]{16}`、PEM 私钥块、常见连接串等）。
- 命中 → 只报告文件:行号与类型（不显示完整密钥）→ 建议"登记入库并从代码中移除，替换为 env 引用"。

### 6.7 紧急销毁（可选启用）

- 用户可预设一个 duress 密保答案：挑战中收到该答案 → 立即销毁内存密钥 + 本地私钥文件安全擦除 → 返回普通"挑战失败"话术（不暴露销毁事实）→ 审计记录暗码。
- 云端密文因无私钥自然不可解；可选联动删除云端 blob。
- 默认关闭，启用需二次确认，防止误触。

## 7. 数据模型与存储

### 7.1 本地目录布局

```
~/.config/dsh-vault/            # 0700，工作区之外（沙箱隔离）
├── vault.json                  # 元数据库（§6.1 schema 数组）+ 密保挑战配置
├── secrets/
│   └── {id}.age                # 每条秘密一个 age 密文（含全部历史版本）
├── keys/
│   ├── identity.key            # age 私钥 0600（可选迁 OS keychain）
│   └── recovery/               # Shamir 分片（本地份）
├── audit.log                   # append-only 审计日志
└── sync-manifest.json          # 同步版本向量
```

写入策略沿用 dsh-storage-json 的做法：临时文件 + fsync + 原子 rename，任何单文件始终是自洽全量。

### 7.2 云端布局

```
<dav-or-bucket>/dsh-vault/
├── secrets/{id}.age            # 与本地同名同内容（E2EE）
├── meta/{id}.age               # 可选：元数据加密副本（便利同步开启时）
└── sync-manifest.json          # 版本向量（不含任何秘密信息）
```

### 7.3 backend 接口化（为方案 C 预留）

```ts
interface VaultBackend {
  put(id: string, blob: Uint8Array): Promise<void>;
  get(id: string): Promise<Uint8Array | null>;
  list(): Promise<{ id: string; hash: string; updatedAt: string }[]>;
  delete(id: string): Promise<void>;
}
// 实现：LocalDirBackend / S3Backend / WebDavBackend / GitBackend / InfisicalBackend
```

切换后端不改变加密边界：E2EE 模式下后端只见密文；InfisicalBackend 模式下可退化为服务端托管（显式配置 + 警示）。

## 8. DSH 集成设计

### 8.1 模型可见工具（host 插件注册）

| 工具 | 入参要点 | 返回给模型的内容 |
|---|---|---|
| `vault_register` | system, account, kind, expires_at, secret 或 from_file, aliases/tags | `{id, fingerprint, masked, strength}` —— 绝无明文 |
| `vault_generate` | system, kind, 长度/字符集策略 | 同上（明文只入库+可选剪贴板） |
| `vault_list` / `vault_search` | 关键词（系统/别名/标签/账号） | 元数据数组（无密文无明文） |
| `vault_challenge` | id 或 scope | 问题文本经 ask_user_question 下发；工具结果只有 pass/fail + 剩余尝试次数 |
| `vault_get` | id, 出口=masked\|clipboard | masked：`ghp_****Xy2`；clipboard：`"已复制，60s 后清除"` |
| `vault_use` | id, 用途描述, 注入方式(env/header/file) + 目标命令 | 执行状态 + 脱敏输出 |
| `vault_totp` | id | 当前 6 位码 + 剩余秒数 |
| `vault_rotate` / `vault_revoke` | id | 状态 + 新版本号 |
| `vault_sync` / `vault_backup` / `vault_import` | 方向/格式 | 同步统计 / 备份文件路径（加密） |
| `vault_audit_report` | 时间范围 | 脱敏审计摘要 |
| `vault_scan_workspace` | 路径 | 命中列表（文件:行:类型，无完整密钥） |
| `vault_scrub` | 会话中某条消息 id | 打码结果确认 |

所有写/读秘密类工具在审批策略 ask 下弹审批卡，卡面只显示元数据与出口类型。

### 8.2 client UI 插件

- **解锁对话框**：主密码输入 → 直连 host RPC（独立通道，不进对话流）→ 解锁态驻留内存，空闲 15 分钟自动锁定。
- **保险库浏览页**：表格仅元数据；行操作：复制（走剪贴板出口+GUI 内二次确认）、编辑元数据、作废。
- **到期提醒卡片** + **密保挑战失败告警**。

具体实现（包形态、slot 挂载点、RPC 面、部署与验收）见 [GUI 表单实现方案](GUI表单实现方案.md)。

### 8.3 skill（SKILL.md 要点）

1. 用户消息中出现疑似密钥 → 主动建议登记，回执绝不复述明文，并提示 T4/T5 风险。
2. 需要密钥执行任务时优先 `vault_use`（代用），其次 clipboard，masked 仅用于人工核对。
3. 禁止把任何工具返回的 masked 值进一步猜测/拼接/写入文件。
4. 写代码需要密钥时一律用环境变量占位（`${GITHUB_TOKEN}`），并提示用户由 vault 注入。
5. 扫描到工作区硬编码密钥 → 报告 + 建议入库并清除。

## 9. 密码学方案细节

### 9.1 原语选型

| 用途 | 算法 | 理由 |
|---|---|---|
| 秘密加密 | age（X25519 + ChaCha20-Poly1305）或 AES-256-GCM | age 文件格式成熟、工具链现成、天然支持多接收者 |
| 主密码派生 | Argon2id (m=64MB,t=3) | 抗 GPU/ASIC 爆破 |
| 密保答案哈希 | Argon2id 独立盐 | 答案熵低，必须慢哈希 |
| 指纹/去重 | SHA-256（截断展示 8 位） | 不泄露原文前提下支持重复检测 |
| 随机生成 | CSPRNG（系统熵源） | — |

### 9.2 主密码与私钥的关系

- age 私钥文件本身再用**主密码派生密钥**加密一层（Argon2id → AES-GCM 包裹）→ 磁盘上拿到 `identity.key` 也无法直接用。
- 解锁 = 主密码解开私钥 → 私钥驻留 host 进程内存（锁定/超时后 zeroize）。
- 密保挑战独立于主密码，作为调取流程的门槛与审计因子。

### 9.3 双因子矩阵

| 因子 | 知道什么 | 经过模型？ |
|---|---|---|
| 密保答案 | 低熵知识 | 是（故只做门槛不做密钥） |
| 主密码 | 高熵知识 | 否（GUI/tty 直连） |
| 设备私钥文件 | 持有物 | — |
| （可选）WebAuthn/硬件密钥 | 持有物 | 否 |

### 9.4 备份与恢复（T9 对策）

- 私钥用 **Shamir 3 分片、阈值 2**：
  - 分片 1：本地 `recovery/`（主密码包裹）；
  - 分片 2：云端（主密码包裹后上传——云端只见密文分片）；
  - 分片 3：打印/手抄离线保存（恢复码格式 `XXXXX-XXXXX-…`）。
- 任意 2 片 + 主密码 → 恢复私钥 → 全库可解。
- `vault_backup export` 另出整库加密快照（age，多接收者：当前公钥 + 备用公钥）。

## 11. 安全边界与残余风险（诚实声明）

1. **聊天录入路径的会话日志**：明文一经发出即存在于本轮上下文与日志投影中。缓解：立即加密入库 + 回执脱敏 + `vault scrub` 打码；但**无法保证模型服务商侧日志**——高价值密钥请走路径 D（本地生成）或 C（GUI 表单）。
2. **IM 平台留存**：IM 通道消息在平台侧的存储不受本插件控制。skill 将在 IM 来源的录入请求回执中固定附带警示。
3. **解锁态窗口**：解锁后 host 进程内存中存在私钥；空闲锁定（默认 15 分钟）缩小窗口，但无法对抗已 root 且实时读内存的攻击者。
4. **代用执行的下游**：`vault_use` 注入 env 后，目标进程若打印环境变量仍可能泄露——helper 对子进程输出做密钥模式过滤（尽力而为）。
5. **密保问题熵低**：不能替代主密码；本设计中它只是流程门槛，真正的密钥学边界是 §9。
6. **元数据不保密**：本地 `vault.json` 元数据明文存储（检索需要）；同机 root 用户可见"有哪些系统的条目"。可选：元数据整体也进 age 密文，检索时解锁后在内存建索引（P2.5 决策点）。
